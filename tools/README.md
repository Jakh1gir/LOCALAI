# tools — инструменты разработки

Исполнитель: Codex. Генератор данных на 10 000 и 100 000 записей, стенд замеров скорости (PERF-01…PERF-12), локальная команда проверки.

## Генератор базы (C-101)

Запустите одну из команд из корня репозитория. Требуются Python 3.13, SQLite 3.45+ и FTS5.

```shell
python -m tools.generate --records 10000 --out base-10000.sqlite3 --seed 1
python -m tools.generate --records 100000 --out base-100000.sqlite3 --seed 1
```

`--records` принимает положительное целое число. `--out` указывает на новый файл в существующем каталоге. Команда возвращает ошибку, если путь уже занят или рядом с ним остались служебные файлы SQLite. По умолчанию `--seed` равен 1. Временная база создаётся рядом с выходным файлом. Генератор заполняет её через `engine` пачками до 1000 записей в одной транзакции, затем закрывает и сохраняет готовый файл.

При одинаковых `--records` и `--seed` совпадают реестры, значения, коды ККС, состав архива и история правок. Движок при каждом запуске назначает новые UUID и служебные отметки времени.

### Состав базы

Одна площадка «ТЭЦ-1», один тип «Оборудование» и два реестра. Около 80 % записей в «В эксплуатации» и 20 % в «Склад». У типа 21 поле.

| Поля | Состав |
| --- | --- |
| ККС | Список кодов вида `10LAC10AP001`. Второй код у 15 % записей. Редкие повторы дают связи между записями, в том числе между реестрами |
| 12 справочников | Категория, наименование, марка, производитель, назначение, тип, диапазон, место установки, состояние, единица измерения, место хранения, документ или акт. От 4 до 400 значений в каждом. У производителей есть синонимы, например «Siemens» и «Сименс» |
| 4 целых числа | Количество, в резерве, неисправно, требуется |
| 2 даты | Последняя и следующая проверки с интервалом 180 или 365 дней |
| 2 текста | Уникальный серийный номер в каждой записи и примечание у 30 % записей |

У 40 % записей от 2 до 4 версий. Правки меняют состояние и количество, некоторые меняют производителя. Около 3 % всех записей в архиве. Архивная операция входит в число версий, поэтому максимальная версия остаётся 4. Доли округляются вниз в каждой пачке, включая неполную.

### Время создания и размер

Замеры полного времени команды с `--seed 1` сделаны на Linux x86_64, AMD EPYC 7763, 9 доступных логических CPU, 9,7 ГиБ ОЗУ, Python 3.13.5 и SQLite 3.46.1. Размер измерен после закрытия базы.

| Записей | Время, с | Размер, байт | Размер, МиБ |
| ---: | ---: | ---: | ---: |
| 10 000 | 16,4 | 37 498 880 | 35,76 |
| 100 000 | 198,6 | 346 783 744 | 330,72 |

## Проверочные вопросы и эталоны (C-105)

Набор [questions/sets/starter.json](questions/sets/starter.json) содержит первые **30 синтетических вопросов**, а не 150 реальных вопросов AI-13. `Q-001`…`Q-020` относятся к оборудованию C-101, `Q-021`…`Q-030` — к модели сигналов C-104. Модель ИИ и Ollama для этих команд не нужны. Установите зависимости проекта из группы `server`.

```shell
python -m tools.questions check
python -m tools.generate --records 10000 --out base-10000.sqlite3 --seed 1
python -m tools.questions run --db base-10000.sqlite3 --out reference-c101.json
```

`run` сначала выполняет ту же проверку набора, что и `check`: отдельный предварительный запуск не обязателен. По умолчанию выполняются 20 вопросов профиля `c101`; число вопросов вне профиля явно печатается и сохраняется в отчёте. Для кабельной базы укажите `--profile c104`, для базы с обоими видами данных — `--profile all`.

```shell
python -m tools.questions run --db signals.sqlite3 --profile c104 --out reference-c104.json
python -m tools.questions run --db combined.sqlite3 --profile all --out reference-all.json
```

Профиль C-104 ожидает реестры «Сигналы» и «Кабели», поля «Код сигнала» и «Тип сигнала». Ключи этих полей берутся из схемы по названиям, пример сигнала — из первой строки по коду. Полномасштабный генератор C-104 пока не входит в `main`; тест C-105 добавляет к C-101 малый стенд из 9 сигналов и 3 кабелей по модели этого задания. Это проверка совместимости формата, а не приёмка нагрузки C-104.

### Как устроен прогон

Стенд снимает согласованную копию SQLite, поднимает LOCALAI на свободном порту `127.0.0.1` и выполняет ожидаемые запросы по HTTP. Исходная база не мигрируется и не получает пользователей стенда. Фоновая обработка документов в копии отключена. Временные роли получают только перечисленные права чтения; пользователь создаётся, входит и меняет временный пароль через API. Вопросы выполняются от его имени. Роли набора — воспроизводимые тестовые политики, а не изменение существующих ролей станции.

В эталоне сохраняются текст вопроса с подставленным кодом, роль, происхождение, ответ и описание запросов-источников. Подсчёты берутся из API/SQL. Случайные UUID заменяются устойчивыми именами, служебные даты создания/правки и непрозрачный курсор не участвуют в сравнении. Значения дат внутри документа записи сохраняются. Статус архива остаётся `null` или `true`. Для записи требуется уникальный ключ либо поле `serial`, `code` или `number`; неизвестный UUID без устойчивого имени завершает вопрос ошибкой. Списки сохраняют порядок API: при вопросе о первых строках задавайте явную сортировку.

Одинаковые данные и seed дают одинаковый JSON эталона. В нём есть хэш проверенного набора, итоги `ok`/`failed`/`manual` и число исключённых вопросов. Ожидаемый `403 forbidden` — правильный ответ на вопрос об отсутствии доступа. Неожиданный статус, код ошибки или отсутствующий путь ответа дают `failed` и код завершения 1. `ok` означает получение ожидаемого ответа базы; это **не оценка качества модели** и не подтверждение порога 95 % AI-14. Текстовые ответы по документам и схемам сохраняются со статусом `manual`, не выдаются за выполненные точные запросы.

`--out` должен указывать на новый файл в существующем каталоге. Существующие файлы, ссылки на них, база и её служебные файлы SQLite не перезаписываются. Пароли и сессии стенда остаются в памяти и временной копии, в эталон не попадают.

### Как инженеру добавить свой вопрос

1. Скопируйте `starter.json` в свой файл и передайте его через `--set путь.json` обеим командам.
2. В `profiles` задайте привязки к нужной площадке и реестрам. `sites`/`datasets` находят объект по точному `name`; у реестра можно уточнить площадку привязкой `site`. `site_of` берёт площадку реестра, `field` — поле по названию, `sample` — пример непустого значения поля. Каждая привязка объявляется после тех, на которые ссылается. Неоднозначное имя отклоняется.
3. В `roles` укажите описание и `datasets`: список имён привязок реестров или `["*"]` для чтения всех. Для сценария AT-28 перечислите только разрешённые реестры.
4. Добавьте вопрос с новым номером, формулировкой инженера и происхождением `вопрос инженера станции`. Вид `kind`: `exact_kks`, `count`, `filter`, `signal_code`, `document` или `diagram`.

Пример вопроса на подсчёт (привязка `operating` и роль `reader` уже есть в стартовом наборе):

```json
{
  "id": "Q-031",
  "text": "Сколько записей эксплуатации с количеством не меньше десяти?",
  "kind": "count",
  "profile": "c101",
  "role": "reader",
  "origin": "вопрос инженера станции",
  "expected": {
    "type": "api",
    "steps": [{
      "name": "total",
      "method": "POST",
      "path": "/api/v1/datasets/{id}/records/count",
      "path_params": {"id": "{{operating.id}}"},
      "body": {"where": [{"field": "quantity", "op": "gte", "value": 10}]}
    }],
    "answer": {"step": "total", "pointer": "/count"}
  }
}
```

`{{имя.поле}}` подставляет привязку или ответ предыдущего шага; ссылка на следующий шаг запрещена. Доступ к элементу списка — например `{{page.items.0.id}}`. `path` берётся из OpenAPI, параметры передаются отдельно. `pointer` — JSON Pointer к нужной части ответа; пустая строка выбирает ответ целиком. По умолчанию ожидается HTTP 200. Для отказа добавьте в шаг `"status": 403, "error_code": "forbidden"` и выберите `/error/code`. Запросы изменения данных и вызовы ИИ в наборе запрещены. Типы значений и операции фильтра дополнительно проверяет настоящий сервер при прогоне.

Для документа или схемы замените `expected` на текст с проверяемым источником; укажите страницу `page` или лист `sheet`, имя документа и ревизию:

```json
{
  "type": "text",
  "answer": "Перед проверкой закрыть клапан согласно инструкции.",
  "source": {"document": "РЭ-001.pdf", "revision": "2", "page": 14}
}
```

Сбор 150 реальных вопросов, проверку документальных источников и сравнение ответов модели с эталоном выполняют на следующих этапах. Для проверки самого инструмента: `python -m pytest tests/e2e/test_questions.py`.

## Стенд замеров (C-102)

Для замеров возьмите синтетическую базу C-101 на 10 000 или 100 000 записей. Команды выполняются из корня репозитория. Нужны Python 3.13 и SQLite 3.45+ с FTS5. Для режима HTTP нужны зависимости сервера.

```shell
python -m tools.bench --db base-10000.sqlite3 --json bench-10000-engine.json
python -m server --db base-10000.sqlite3
```

Пока сервер работает, в другом терминале выполните следующую команду.

```shell
python -m tools.bench --db base-10000.sqlite3 --http http://127.0.0.1:8730 --json bench-10000-http.json
```

Для 100 000 записей замените имя базы и имена отчётов. Стенд печатает таблицу Markdown и пишет JSON. Если не задать `--json`, отчёт сохраняется в `bench.json`. Для каждой операции по умолчанию выполняются 5 разогревочных вызовов и 30 замеров. `--repeats` увеличивает число замеров. Прогоны чередуют операции чтения и одиночную правку, чтобы усреднить влияние кратковременной нагрузки.

- Стенд читает реестр «В эксплуатации». Для глубокой страницы курсор готовится заранее. Поиск использует фразу «насос питательн», фильтр выбирает Siemens и ABB в диапазоне количества от 10 до 25 включительно и сортирует по дате следующей проверки.
- В режиме ядра стенд читает временный снимок базы. Для каждой пакетной вставки он создаёт свежую копию снимка и измеряет одну транзакцию с фиксацией 1000 новых записей. Время подготовки копии и данных находится за пределами замера.
- В режиме HTTP чтение идёт через `urllib` к серверу с теми же данными, что и в `--db`. Для правки стенд запускает тот же сервер на временной копии и свободном порту на `127.0.0.1`. В API v1 пока нет пакетного маршрута, поэтому для PERF-04 режим HTTP показывает «не измерено».
- Отчёт даёт P50, P95 и максимум. Для операций с числовой целью ТЗ оценка делается по P95. Размер учитывает весь файл снимка SQLite с индексами и делится на общее число записей в обоих реестрах. Цель NFR-02 составляет 3000 байт на запись.

Для проверки повторяемости запустите одну команду дважды подряд с разными путями `--json`. Для каждой операции разделите абсолютную разницу медиан на медиану первого прогона и сравните результат с 20 %.

## Проверочные вопросы ИИ (C-105)

Набор [questions/sets/starter.json](questions/sets/starter.json) содержит 30 **синтетических** вопросов: 20 по оборудованию C-101 и 10 по модели сигналов и кабелей C-104. Команды требуют зависимостей `server` из корня проекта. Модель и служба ИИ не вызываются: выполняются ожидаемые запросы к настоящему HTTP API, их ответы становятся эталоном для последующей оценки ИИ.

```shell
python -m tools.questions check
python -m tools.questions run --db base-10000.sqlite3 --out reference-c101.json
```

`run` сначала выполняет ту же проверку, что `check`, затем поднимает сервер на свободном порту `127.0.0.1` с временным согласованным снимком SQLite. Исходные данные не перезаписываются. Чтение живой базы учитывает зафиксированный WAL; SQLite может создать служебные `-wal`/`-shm`, стенд их не удаляет. Во временной копии создаются случайные учётные записи и роли; вход, смена временного пароля и выдача прав идут через API. Роли набора — отдельные воспроизводимые политики чтения, а не правка ролей станции. Фоновая обработка документов в копии отключена. Пароли и токены не попадают в эталон.

По умолчанию выбирается профиль `c101`, а десять вопросов C-104 явно отмечаются как исключённые. Для кабельной базы или базы с обоими наборами данных:

```shell
python -m tools.questions run --db signals.sqlite3 --profile c104 --out reference-c104.json
python -m tools.questions run --db combined.sqlite3 --profile all --out reference-all.json
```

Профиль C-104 ищет реестры «Сигналы» и «Кабели», поля «Код сигнала» и «Тип сигнала». Ключи полей берутся по названиям из API схемы, пример — из первой непустой строки по коду сигнала. Полный генератор C-104 пока не находится в `main`; совместимость проверена на отдельном малом стенде по его модели: 9 сигналов, 3 кабеля и несколько сигналов на аппарат. Этот стенд в `tests/e2e/question_data.py` не заменяет генератор нагрузки C-104.

### Что означает эталон

В JSON сохраняются формулировка с подставленным кодом, вид, роль, происхождение, ответ и описание запросов-источников. Подсчёты берутся из API/SQL. Случайные UUID заменяются устойчивыми именами площадок, реестров, ККС, значений справочников и записей. Записи опознаются по уникальному полю либо по `serial`, `code` или `number`; UUID без устойчивого имени даёт ошибку. Служебные даты создания и правки, ID базы и непрозрачный курсор исключены из сравнения. Значения внутри `doc`, включая даты, сохраняются; признак архива представлен `null` или `true`. Порядок строк сохраняется: для вопроса о первых строках задавайте сортировку.

Результат содержит хэш проверенного набора и итоги `ok`, `failed`, `manual`. Ожидаемый `403 forbidden` — правильный результат вопроса об отсутствии доступа. Неожиданный статус, код ошибки или отсутствующий путь ответа дают `failed` и код завершения 1. Текстовые ответы по документам и схемам имеют статус `manual` и не считаются выполненными точными запросами. `ok` означает получение ответа базы по спецификации вопроса; это **не процент правильных ответов модели** и не подтверждение AI-14. Сбор 150 реальных вопросов и сравнение ИИ с эталоном остаются отдельной работой.

При одинаковых данных и seed эталон воспроизводим. Для сравнения используйте новые пути `--out`: существующий файл, ссылка на него, исходная база и её служебные пути не перезаписываются. В эталоне нет текущего времени и абсолютного пути базы.

### Как инженеру добавить вопрос

1. Скопируйте стартовый JSON в свой файл; укажите его через `--set station-questions.json` в обеих командах.
2. Настройте `profiles`: описание и `bindings`. Привязка `sites`/`datasets` находит точное `name`; у реестра можно уточнить площадку ссылкой `site`. `site_of` получает площадку реестра, `field` — поле по названию, `sample` — пример значения поля. Привязки объявляются в порядке зависимостей; неоднозначное имя отклоняется.
3. В `roles` задайте описание и `datasets`: имена привязок разрешённых реестров или `["*"]` для чтения всех. Для AT-28 не включайте кабели в разрешённый список.
4. Добавьте новый уникальный номер `Q-031`, свою формулировку, `profile`, `role` и происхождение `вопрос инженера станции`. Виды `kind`: `exact_kks`, `count`, `filter`, `signal_code`, `document`, `diagram`.

Пример вопроса на подсчёт с уже существующими привязкой `operating` и ролью `reader`:

```json
{
  "id": "Q-031",
  "text": "Сколько записей эксплуатации с количеством не меньше десяти?",
  "kind": "count",
  "profile": "c101",
  "role": "reader",
  "origin": "вопрос инженера станции",
  "expected": {
    "type": "api",
    "steps": [{
      "name": "total",
      "method": "POST",
      "path": "/api/v1/datasets/{id}/records/count",
      "path_params": {"id": "{{operating.id}}"},
      "body": {"where": [{"field": "quantity", "op": "gte", "value": 10}]}
    }],
    "answer": {"step": "total", "pointer": "/count"}
  }
}
```

`path` берётся из OpenAPI; параметры пути и строки запроса передаются отдельно в `path_params` и `query`. Запросы записи, служебные маршруты и вызовы ИИ запрещены. Тело проверяется моделью API, операции фильтров — по языку запросов; существование полей и приведение значений дополнительно проверяет сервер при прогоне.

`{{имя.поле}}` ссылается на привязку или ответ предыдущего шага. Например, после шага `object` с `resolve` карточка использует `{{object.id}}`. Элемент списка — `{{page.items.0.id}}`; исполнения кода в подстановках нет. `answer.pointer` — JSON Pointer к части ответа, пустая строка выбирает весь ответ. По умолчанию ожидается HTTP 200. Для отказа укажите в шаге `"status": 403, "error_code": "forbidden"` и выберите `/error/code`.

Для вопроса по документу или схеме замените `expected` на текст с источником. Обязательны имя документа, ревизия и страница `page` либо лист `sheet`. Пример содержимого `expected`:

```json
{
  "type": "text",
  "answer": "Перед проверкой закрыть клапан согласно инструкции.",
  "source": {"document": "РЭ-001.pdf", "revision": "2", "page": 14}
```
