# Язык запросов

Один язык для таблицы в интерфейсе, экспорта и инструментов ИИ (API-04). Запрос — объект JSON; сервер переводит его в SQL и никогда не читает реестр в память целиком (API-03).

## Запрос

```json
{
  "where": [
    {"field": "f3", "op": "gte", "value": 400},
    {"any": [
      {"field": "f4", "op": "eq", "value": "Siemens"},
      {"field": "f4", "op": "empty"}
    ]}
  ],
  "search": "насос пэн",
  "sort": {"field": "f3", "dir": "desc"},
  "limit": 50,
  "cursor": null,
  "archived": false,
  "kks": null
}
```

Все параметры необязательны. Пустой запрос возвращает первую страницу действующих записей в порядке создания.

| Параметр | Значение |
| --- | --- |
| `where` | Список условий, до 30. Условия списка соединены через «И» |
| `search` | Строка поиска по всем полям записи |
| `sort` | Одно поле и направление `asc` или `desc` |
| `limit` | Размер страницы, от 1 до 200; по умолчанию 50 |
| `cursor` | Значение `next_cursor` предыдущей страницы |
| `archived` | `false` — действующие (по умолчанию), `true` — только архив, `"any"` — все |
| `kks` | UUID объекта ККС: только записи, связанные с ним любой ролью |

## Условия

Условие — `{"field", "op", "value"}`. Группа `{"any": [условия]}` соединяет простые условия через «ИЛИ»; вложенные группы не допускаются.

`field` — ключ поля типа или системное поле: `$id`, `$version`, `$created_at`, `$updated_at`.

| Операция | Смысл | Виды полей |
| --- | --- | --- |
| `eq`, `ne` | равно, не равно | все |
| `lt`, `lte`, `gt`, `gte` | сравнение | `text`, `integer`, `number`, `date` |
| `in` | одно из списка, до 500 значений | все, кроме `boolean` |
| `contains`, `starts` | содержит, начинается с — без учёта регистра; для ККС — с той же нормализацией Unicode, что и сам код | `text`, `integer`, `number`, `date`, `choice`, `kks` |
| `empty`, `not_empty` | не заполнено, заполнено | все |

Правила значений:

- Значение приводится по виду поля так же, как при записи: `"250,5"` для числа, `"01.01.2024"` для даты.
- Для `choice` значение — название, синоним или UUID значения справочника. Неизвестное название не даёт совпадений.
- Для `kks` значение — код, псевдоним или UUID объекта. Регистр и внешние пробелы не важны.
- Для `record` доступны `eq`, `ne`, `in`, `empty`, `not_empty`; значение — UUID записи-цели или значение её уникального поля (номер кабеля). Неизвестное значение не даёт совпадений.
- `ne` включает записи с пустым полем.
- Для поля с несколькими значениями `eq`, `in`, `contains`, `starts` означают «хотя бы одно значение подходит», `ne` — «ни одно не равно».
- `eq` по тексту — точное совпадение с учётом регистра; для поиска без учёта регистра служат `contains`, `starts` и `search`.

## Поиск

Строка `search` делится на слова по пробелам; запись подходит, если в ней встречается каждое слово — как часть любого поля, включая названия значений справочников и коды ККС. Регистр не важен, «ё» приравнена к «е». Слова от трёх символов ищутся по индексу; слова из одного-двух символов — перебором записей реестра, это медленнее.

## Сортировка и страницы

- Сортировка — по одному полю; при равных значениях порядок задаёт время создания. Пустые значения идут первыми при `asc` и последними при `desc`.
- Поле вида `choice` сортируется по названию значения, `kks` — по коду. По полю с несколькими значениями сортировать нельзя.
- Текст сортируется по кодам символов: заглавные раньше строчных. Сортировка по правилам русского алфавита — отдельная задача.
- Страницы листаются по курсору (API-05): в ответе приходит `next_cursor`, его передают в следующем запросе вместе с теми же `where`, `search` и `sort`. `null` означает последнюю страницу. Курсор привязан к сортировке; с другой сортировкой или с повреждённым содержимым он отклоняется — `400 query_invalid` с полем `cursor`. Следующая страница начинается сразу с места курсора по индексу, сколько бы страниц ни было пролистано. Это верно и внутри длинной группы одинаковых значений поля сортировки.
- Курсор — позиция в порядке сортировки, а не снимок реестра. Если между страницами запись изменили так, что она переместилась через границу страницы, она может встретиться дважды или не встретиться. Интерфейс показывает строки по UUID без повторов, а при изменении реестра (события API-09, этап 3) загружает выдачу заново с первой страницы.
- Число записей по условиям отдаёт отдельный запрос подсчёта с теми же `where`, `search`, `archived`, `kks`.

## Ответ

```json
{
  "items": [
    {
      "id": "0f7c…",
      "dataset_id": "5a1e…",
      "version": 3,
      "doc": {"f1": "9b2d…", "f2": "Насос питательный ПЭН-1", "f3": 500, "f4": "c41a…"},
      "archived_at": null,
      "created_at": "2026-11-17T09:30:00.000Z",
      "updated_at": "2026-11-17T10:02:11.512Z"
    }
  ],
  "next_cursor": "WyI4…",
  "refs": {
    "choices": {"c41a…": "Siemens"},
    "kks": {"9b2d…": "10LAC10AP001"},
    "records": {"77aa…": "5011"}
  }
}
```

`refs` содержит названия для всех UUID справочников, ККС и записей-целей ссылок, встретившихся на странице; подпись записи — значение её первого уникального поля, иначе первого текстового. Интерфейс показывает название из `refs`, а при правке отправляет либо `{"id": "<UUID>"}`, либо текст — название значения или код ККС.

## Ошибки

Неверный запрос отклоняется целиком с кодом `query_invalid` и указанием поля. Частичного выполнения нет.
