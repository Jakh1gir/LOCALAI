# C-003 · Токены дизайна и макеты трёх экранов

**Исполнитель:** Codex · **Ветка:** `codex/c-003-design` · **Каталоги:** `web/` · **Требования:** UI-01, UI-07, UI-08, раздел 11.1 ТЗ

## Зачем

По UI-01 код экранов пишется только по макетам, которые согласовал владелец. Это первые три экрана, с которыми работают каждый день.

## Что сделать

1. **Токены в одном файле:** цвета, отступы, шрифты, радиусы, тени; светлая и тёмная темы; плотный и свободный режим таблицы (UI-07).
2. **Набор базовых компонентов** — список до 15 штук с назначением каждого (UI-08). Реализация — в C-103 и далее.
3. **Макеты** — статические страницы на этих токенах, открываются в браузере без сервера (`web/mockups/`):
   - **реестр**: таблица на 50 видимых строк из 10 000, фильтр по столбцу, поиск, выделенная строка, правка ячейки, сообщение о конфликте версий;
   - **инспектор записи**: рядом с таблицей — данные, связи ККС, история версий;
   - **карточка ККС**: записи объекта по реестрам и ролям, псевдонимы, место под документы и листы схем.
   Данные правдоподобные: коды вида `10LAC10AP001`, русские названия, реестры «В эксплуатации» и «Склад».
4. Каждый макет — в светлой и тёмной теме; один — в плотном и свободном режиме.

## Результат

`web/mockups/`, файл токенов, `web/README.md` с перечнем компонентов. В описании PR — снимки экрана всех макетов, чтобы владелец мог согласовать их, не запуская проект.

## Приёмка

Владелец согласует макеты или пишет замечания в PR. До согласования C-103 не начинается.
