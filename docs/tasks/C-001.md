# C-001 · Локальная проверка одной командой

**Исполнитель:** Codex · **Ветка:** `codex/c-001-check` · **Каталоги:** `tools/` · **Требования:** CI-01, CI-03…CI-06

## Зачем

Проверка перед pull request должна быть одной командой и проходить локально, без расхода минут GitHub Actions.

## Команда

```shell
python -m tools.check
```

По порядку, с остановкой на первой ошибке:

1. `python -m pytest`;
2. `python -m server.openapi --check` — описание API совпадает с кодом;
3. стиль — `ruff check` и `ruff format --check`, если ruff установлен. Если нет — сообщить и пропустить, не считая это ошибкой. Настройки ruff уже есть в `pyproject.toml`.

В конце — короткий итог: что прошло, что пропущено, сколько секунд заняло.

## Черновик workflow — не включать

Положить в `tools/ci/pr-check.yml` (не в `.github/`, поэтому он не запускается):

- запуск только на `pull_request` в `main` и вручную (`workflow_dispatch`);
- `paths-ignore` для `docs/**` и `*.md`;
- `concurrency` с `cancel-in-progress: true`;
- одна задача на `ubuntu-latest`, `timeout-minutes: 5`;
- кэш pip, установка `.[server,dev]`, затем `python -m tools.check`;
- без артефактов.

В `.github/workflows/` он попадёт отдельной задачей после явного подтверждения владельца.

## Приёмка

`python -m tools.check` проходит на чистом клоне. Описание PR содержит ожидаемое время работы черновика workflow и объяснение, почему он не запустится на изменениях документов.
