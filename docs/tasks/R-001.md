# R-001 · Проверка кода Claude

**Исполнитель:** Codex · **Ветка:** `codex/r-001-review` · **Каталоги:** только `docs/requests/`

## Зачем

Pull request #1 (импортёр Local_DB) и #2 (сервер API) слиты без перекрёстной проверки, которой требует пункт 3.4 правил. Нужен второй взгляд до того, как на этот код опрётся интерфейс.

## Что сделать

1. Прочитать `engine/`, `server/`, `server/localdb_import/` и их тесты; запустить `python -m pytest`.
2. Попробовать сломать поведение, а не стиль:
   - граничные значения: пустые и очень длинные строки, даты, числа, коды ККС с пробелами и разными алфавитами;
   - курсор страниц при правках между страницами, сортировка с пустыми значениями;
   - одновременные правки одной записи, ключ идемпотентности;
   - откат версии с архивными значениями справочника и архивными объектами ККС;
   - повторный импорт Local_DB после правок в обеих системах;
   - ошибки API: формат, код HTTP, текст на русском, отсутствие внутренних подробностей.
3. Сверить код с контрактом `docs/contract/` и требованиями ТЗ: DATA-01…DATA-11, API-01…API-11, MIG-02…MIG-13.

## Результат

Один файл `docs/requests/001-claude-review.md` по шаблону из `docs/requests/README.md`. По каждой находке:

- серьёзность: «теряются или портятся данные» / «неверное поведение» / «неудобство или расхождение с документом»;
- где: файл и строка;
- как воспроизвести: короткий код или запрос;
- что ожидалось и что получилось.

Код Claude не править. Если находок нет — так и написать, перечислив, что именно проверено.

## Приёмка

Каждая находка воспроизводится по описанию. Claude отвечает в том же файле: принято, исправлено в PR №…, или отклонено с причиной.
