# C-302 · Экраны мастера импорта Excel

**Исполнитель:** Codex · **Ветка:** `codex/c-302-import-wizard` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** K-305 (сервер мастера) · **Требования:** ТЗ 6.1, IMP-01…17, UI-05, UI-12, AT-04…08, AT-41

Контракт — [api-v1.md, «Импорт Excel»](../contract/api-v1.md#импорт-excel). Всё решает сервер: экран показывает план и отправляет решения, строки книги на применение не отправляет (IMP-03).

## Что сделать

1. **Вход в мастер** — команда «Импорт» в оболочке и кнопка в реестре (с выбранным реестром). Видна, если у роли есть `import` хоть на один реестр или раздел `structure`.
2. **Файл** — выбор `.xlsx`, загрузка `POST /imports?name=` телом-файлом с индикатором.
   - Листы из ответа: число строк и столбцов.
   - Таблица `top` с выбором строки заголовков; по умолчанию — `header_row` сервера.
   - Ошибки пределов IMP-11 — текстом сервера у поля файла.
3. **Назначение и сопоставление** — `GET /imports/{id}/preview`.
   - Если пришёл `profiles`, предложить профиль первым; выбор подставляет `mapping`, `key` и режим.
   - **Режим `records`.** Выбор реестра (только с правом `import`). Сопоставление «столбец → поле» с подсказкой `suggested.mapping`; столбцы «UUID» и «Версия» шаблона выгрузки показаны как служебные. Ключ — только из уникальных полей; код ККС объекта ключом не предлагается.
   - **Режим `new_type`** (только с `structure`). Название типа и реестра, площадка; для каждого столбца — название поля, вид и признак «ключ».
   - **Режим `magnet`.** Если `suggested.mode` — `magnet`, показать роли столбцов из `suggested.layout`: ККС, код сигнала, кабель, места и их клеммы, канал. Указать имя раскладки и площадку; реестры «имя — сигналы» и «имя — кабели» видны заранее.
4. **Проверка** — `POST /imports/{id}/plan`, затем сводка `counts` и таблица `GET /imports/{id}/rows` с фильтром по `action`.
   - У изменённой строки видно «было → станет» из `changes`.
   - У спорной — причина и выбор «Пропустить / Применить поверх», где «Применить поверх» есть только для `version_conflict` (`PUT …/decision`).
   - Для магнита — `plan` и `issues`: расхождения магнита.
5. **Применение** — `POST /imports/{id}/apply`, по желанию с названием профиля.
   - Ответ `409 import_stale` объясняет, что данные изменились, и предлагает построить план заново (повтор `plan`).
   - `409 import_failed` показывает строку.
6. **Отчёт** — счётчики, пропущенные строки с причинами, переход в реестр (`dataset_id`) или в реестры раскладки.
7. **Профили** — список `GET /import-profiles` с удалением (автору и администратору).
8. **Сценарии в браузере** (UI-12) на настоящем сервере:
   - книга с заголовком не в первой строке;
   - импорт в реестр: новые, изменённые, без изменений, повтор ключа, ошибка значения;
   - устаревший план после правки записи в другом окне;
   - шаблон выгрузки с UUID и правкой после выгрузки, «Применить поверх»;
   - новый тип;
   - таблица сигналов магнитом и повторная загрузка той же книги без изменений;
   - профиль, предложенный для второй книги того же вида.

## Приёмка

Сценарии п. 8 проходят на сервере с базой генератора C-101 (магнит — на базе C-104 или вымышленной книге в тесте). Без права импорта мастер не показывается. Макет мастера — в стиле C-003; если нужен отдельный макет, покажите его владельцу до кода (UI-01).
