# C-103 · Экран реестра

**Исполнитель:** Codex · **Ветка:** `codex/c-103-registry` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** C-002, согласованных макетов C-003 · **Требования:** UI-02…UI-04, UI-09, API-04, API-05, PERF-01

## Что сделать

Экран реестра по согласованному макету на Tabulator через клиент API из C-002:

1. **Выбор реестра**: площадка, тип, реестр; столбцы строятся по полям типа (`GET /types/{id}`).
2. **Страницы по курсору** (UI-02): первые 50 строк, затем догрузка при прокрутке по `next_cursor`. Смена реестра, фильтра, поиска или сортировки сбрасывает загруженные страницы; запоздалые ответы отбрасываются. Строки показываются по UUID без повторов (см. «Сортировка и страницы» в `docs/contract/query-language.md`).
3. **Названия** значений справочников и кодов ККС — из `refs` ответа; в ячейке видно название, в правку уходит UUID или текст.
4. **Фильтр по столбцу и поиск** — на языке запросов, без чтения реестра целиком в браузер.
5. **Правка ячейки** (UI-03): значение видно сразу, запрос несёт `expected_version` и `Idempotency-Key`; при отказе значение возвращается и показывается причина из `message`, при `409 version_conflict` — различие версий.
6. **Клавиатура** (UI-04): стрелки, Enter — правка, Esc — отмена, Ctrl+C диапазона.
7. **Сценарии в браузере** (UI-12) в `tests/e2e/`: открыть реестр, долистать до 1000-й строки, отфильтровать, исправить ячейку, получить конфликт.

## Приёмка

На заглушке и на настоящем сервере с базой генератора C-101 на 10 000 записей: первые 50 строк появляются за P95 ≤ 500 мс от действия (PERF-01), прокрутка без зависаний. Замеры — в описании PR.
