# C-102 · Стенд замеров

**Исполнитель:** Codex · **Ветка:** `codex/c-102-bench` · **Каталоги:** `tools/` · **Зависит от:** C-101 · **Требования:** PERF-01, PERF-02, PERF-04, PERF-07, NFR-02

## Зачем

Цели скорости в разделе 13 ТЗ проверяются одинаковым стендом, а не разовыми замерами. Отчёт стенда — доказательство на шлюзах этапов.

## Команды

```shell
python -m tools.bench --db base.sqlite3                         # прямо через engine
python -m server --db base.sqlite3                              # в другом окне
python -m tools.bench --db base.sqlite3 --http http://127.0.0.1:8730
```

Базу бенч не меняет: замер загрузки и правки идёт на временной копии.

## Что мерить

| Замер | Цель ТЗ |
| --- | --- |
| Первая страница, 50 записей | PERF-01 |
| Страница по курсору в глубине (после 20 страниц) | — |
| Точный код ККС, без учёта регистра | PERF-02 |
| Карточка ККС | — |
| Поиск подстроки из двух слов | PERF-07 |
| Фильтр по списку и по диапазону числа с сортировкой по дате | — |
| Подсчёт по фильтру | — |
| Загрузка 1000 записей одной транзакцией | PERF-04 |
| Правка одной записи | — |
| Размер файла на запись | NFR-02 |

Значения целей взять из раздела 13 ТЗ; если для замера цели нет — показать без оценки.

## Как мерить

- Прогрев, затем не меньше 30 повторов; медиана и 95-й процентиль.
- HTTP — через `urllib` из стандартной библиотеки, без сторонних клиентов.
- Итог — таблица Markdown в консоль и файл JSON; у каждого замера пометка «в норме» или «не в норме» относительно цели.
- В отчёт — характеристики машины: процессор, память, ОС, версии Python и SQLite.

## Результат

- `tools/bench.py` и раздел в `tools/README.md`.
- В описании pull request — отчёты на 10 000 и 100 000 записей, через engine и через HTTP.

## Приёмка

Отчёт повторяется: два прогона подряд дают медианы в пределах 20 % друг от друга. Замер, не уложившийся в цель, не скрывается, а записывается в `docs/STATE.md`.
