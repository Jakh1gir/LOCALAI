# C-105 · Набор проверочных вопросов ИИ: формат и прогон точных вопросов

**Исполнитель:** Codex · **Ветка:** `codex/c-105-question-set` · **Каталоги:** `tools/`, `tests/e2e/` · **Зависит от:** — · **Требования:** AI-03, AI-04, AI-13, AI-14, AT-25, AT-26, AT-34, AT-43

ТЗ требует собирать набор проверочных вопросов с этапа 0 (раздел 17): без него качество ИИ на этапе 5 нечем измерить. Модель и ИИ-служба для этого задания не нужны. Сначала нужен формат и прогон вопросов, у которых есть точный ответ из базы.

## Что сделать

1. **Формат набора** — один файл на вопрос или общий YAML/JSON. Для каждого вопроса:
   - текст вопроса так, как его задал бы инженер;
   - вид: точный ККС, подсчёт, фильтр, код сигнала, документ, схема;
   - ожидаемый ответ — либо **запрос к API**, результат которого и есть верный ответ (`POST …/records/count` с условиями, `resolve`, карточка ККС), либо текст с источником для вопросов по документам;
   - роль, от имени которой задаётся вопрос (для AT-28: кабели не видны тому, у кого нет права);
   - происхождение: «придуман по базе генератора» или «вопрос инженера станции».
2. **Валидатор** `python -m tools.questions check`: формат, уникальные номера, ожидаемые запросы проходят по контракту.
3. **Прогон точных вопросов** `python -m tools.questions run --db …`: выполняет ожидаемые запросы на настоящем сервере и сохраняет «эталон» — ответы базы. На этапе 5 ИИ будет сравниваться с этим эталоном (AI-14).
4. **Первые 30 вопросов** по базам генератора C-101 и C-104: точный ККС, код сигнала (AT-43), подсчёты (AT-26), вопрос от роли без права на реестр (AT-28).
5. В `tools/README.md` — как инженеру станции добавить свой вопрос.

## Приёмка

`check` и `run` проходят одной командой на базе генератора; эталон воспроизводим при том же seed. Кто соберёт 150 реальных вопросов инженеров, решает владелец (ТЗ, 19.2) — это задание даёт им форму и прогон.
