# C-301 · Панель общего чата и живое обновление экранов

**Исполнитель:** Codex · **Ветка:** `codex/c-301-chat` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** K-303 (сервер чата и событий) · **Требования:** CHAT-01…08, UI-05, UI-06, UI-12, AT-44

Контракт — [api-v1.md, «Общий чат» и «События»](../contract/api-v1.md#общий-чат). Чат людей между собой отделён от панели ИИ (раздел 9 ТЗ): у них разные экраны и разные маршруты.

## Что сделать

1. **Клиент событий** — один на приложение (UI-09).
   - Без `after` он получает `cursor`, затем повторяет `GET /events?after=<cursor>&wait=25`.
   - При `more: true` — следующий запрос сразу; при ошибке сети — повтор с нарастающей паузой до 10 с.
   - Подписчики получают события по `kind`: `record`, `dataset`, `chat_message`, `kks`, структура.
   - Вкладка браузера в фоне продолжает слушать; после разрыва пропущенное догружается по курсору.
2. **Живое обновление таблицы реестра** (UI-06): событие `record.*` с `dataset_id` открытого реестра обновляет строки без перезагрузки. Позиция прокрутки, фильтры и выделение сохраняются.
3. **Панель общего чата** (раздел оболочки; виден при `chat` в `permissions.sections` из `GET /auth/me`).
   - **Лента.** `GET /chat/messages`: при прокрутке вверх — `before=<first>`, по событию `chat_message` и после разрыва — `after=<last>`.
   - **Отправка.** Поле ввода видно при `chat_write`. Enter отправляет, Shift+Enter — новая строка; счётчик знаков до 4000. Отказ `429 chat_rate_limit` показывается у поля.
   - **Ссылки** — из `refs` по `start`/`end`:
     - `kks` открывает карточку ККС;
     - `record` с `access: true` — инспектор записи, с `access: false` — подпись «нет доступа» без ссылки;
     - `document` — «нет доступа» до этапа 4.
   - **Вставка ссылки на запись.** Кнопка «Поделиться в чат» в инспекторе вставляет `[[record:UUID]]`.
   - **Свои сообщения.** Действия по `can`: «Изменить» (`PATCH`, с `version`), «Удалить» (с подтверждением, общий диалог C-202), «История». Конфликт `409 version_conflict` предлагает обновить ленту.
   - **Модератор.** «Скрыть» с необязательной причиной и «Вернуть». Удалённое и скрытое сообщение у других показывается отметкой без текста.
   - **Непрочитанное.** Счётчик `unread` — в оболочке у раздела чата. Когда последнее сообщение видно в ленте, отправляется `POST /chat/read` с его `seq`.
   - **Поиск** — `GET /chat/search?q=`, переход к сообщению в ленте.
4. **Сценарии в браузере** (UI-12), два пользователя в двух контекстах браузера на одном сервере:
   - сообщение первого появляется у второго без перезагрузки до 1 с (AT-44);
   - ссылка ККС открывает карточку, запись без права — «нет доступа»;
   - правка видна у второго, история открывается автору;
   - модератор скрывает, у автора — отметка;
   - строка, созданная первым в открытом реестре, появляется у второго без потери прокрутки и фильтра.

## Приёмка

Сценарии п. 4 проходят на сервере с базой генератора C-101. Без раздела `chat` в правах панель не показывается и не запрашивает `/chat/*`. Без `chat_write` поля ввода нет. Внешних запросов нет (UI-11). Макет панели — в стиле C-003; если нужен отдельный макет, покажите его владельцу до кода (UI-01).
