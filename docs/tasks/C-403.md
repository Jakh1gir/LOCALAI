# C-403 · Экран знаний: очередь проверки, заметки, словарь

**Исполнитель:** Codex · **Ветка:** `codex/c-403-knowledge` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** K-402 · **Требования:** KNOW-06…10, ТЗ 11.1 («Знания»), UI-05, UI-12, AT-29, AT-30

Контракт — [api-v1.md, «Знания»](../contract/api-v1.md#знания).

## Что сделать

1. **Раздел «Знания» → «Очередь».** Видна при разделе `knowledge`.
   - Предложенные и устаревшие заметки из `GET /knowledge/queue` со счётчиками.
   - У устаревшей — причина (`stale_reason`) и источники «было — стало» (`version` → `current_version`) со ссылками.
   - Действия: «Подтвердить» (для устаревшей — «Проверено, верно»), «Отклонить» с причиной, «Исправить».
   - Счётчик очереди — в оболочке, обновляется по событиям (`kind: knowledge_note`).
2. **Заметки.** Список подтверждённых с поиском и фильтром по ККС и типу.
   - Карточка заметки: текст, на что (ККС, тип, станция), источники — открывают запись, документ на странице, карточку ККС; автор, подтвердивший, даты.
   - «Предложить заметку» доступно всем вошедшим: из карточки ККС, из инспектора записи (источник подставляется), из карточки документа (со страницей).
3. **Словарь станции** (при `knowledge` — правка, остальным — просмотр): термин, значение, объекты ККС; добавить, изменить, удалить; конфликт `term_taken` — у поля.
4. **Поиск Ctrl+K** (C-304): группы «Заметки» и «Словарь»; объект, найденный по словарю, — с пометкой «по словарю: ПЭН-1».
5. **Сценарии в браузере** (UI-12):
   - инженер предлагает заметку → администратор подтверждает → заметка находится поиском;
   - правка записи-источника → заметка в очереди как устаревшая с причиной (AT-29);
   - термин словаря находит объект по официальному коду (AT-30);
   - роль без права на реестр источника не видит заметку ни в списке, ни в поиске.

## Приёмка

Сценарии п. 5 проходят на настоящем сервере. Без раздела `knowledge` очереди нет, словарь только для чтения.
