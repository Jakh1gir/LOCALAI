# C-201 · Экраны пользователей, ролей и матрицы прав

**Исполнитель:** Codex · **Ветка:** `codex/c-201-access-screens` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** K-201 (слит), запрос 003 (экран входа слит, PR #17) · **Требования:** ROLE-01…ROLE-08, UI-01, UI-12

Перед началом прогоните `npm run check`, `npm run build` и `npm run test:browser` на `main`. Экран входа из PR #17 Claude писал без сборки: в его среде нет пакетов npm. Найденные ошибки исправьте первым коммитом этой ветки.

## Что сделать

Раздел «Администрирование» (`/admin`); он виден роли с разделом `admin` в `permissions.sections` ответа `GET /auth/me`. Контракт — [api-v1.md, «Вход и права»](../contract/api-v1.md#вход-и-права).

1. **Пользователи** (`GET /users`). Таблица: логин, имя, роль, состояние (активен, заблокирован, нужно сменить пароль, вход временно закрыт), последний вход. Действия:
   - создать (`POST /users`) — показать `temporary_password` один раз, с кнопкой копирования и предупреждением, что повторно его не увидеть;
   - сменить имя или роль (`PATCH /users/{id}`);
   - заблокировать и разблокировать;
   - сбросить пароль — тоже с показом временного пароля один раз.
2. **Роли** (`GET /roles`). Создать, копировать (`copy_from`), переименовать, отключить и вернуть. Число пользователей у роли видно в списке.
3. **Матрица прав** роли (`GET /roles/{id}`, `PUT /roles/{id}/permissions`). Подписи — из `GET /auth/permissions`.
   - Разделы — флажки.
   - Реестры — строка «Все реестры» (`target: "*"`) и строки выбранных реестров; столбцы — действия: `view`, `create`, `edit`, `archive`, `purge`, `import`, `export`.
   - Поля — ограничения «не видеть» и «не править» по полям типа.
   - Сохранение отправляет матрицу целиком. До отправки видно, что добавлено и что снято.
4. **Отказы сервера** показываются текстом из `message` у нужного элемента: `409 last_admin` — у действия, которое отклонено; `permission_invalid` — у строки матрицы по `field` (`permissions.N`).
5. **Разрешённые адреса** (`/system/allowed-ips`): список, добавить сеть, убрать. Отказ `409 network_lockout` объясняет, что адрес администратора выпадет из списка.
6. **Сценарии в браузере** (UI-12) на настоящем сервере: создать роль копией «Инженера», снять право `create` на реестр, создать пользователя, войти им временным паролем, сменить пароль, убедиться, что создание записи отклонено; попытаться заблокировать последнего администратора и увидеть отказ.

## Приёмка

Сценарии п. 6 проходят на сервере с базой генератора C-101. Экран без раздела `admin` в правах не показывается и не запрашивает `/users`. Макет раздела — в стиле C-003; если нужен отдельный макет, покажите его владельцу до кода (UI-01).
