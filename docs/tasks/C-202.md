# C-202 · Доработки администрирования: подтверждения и правило кода ККС

**Исполнитель:** Codex · **Ветка:** `codex/c-202-admin-followups` · **Каталоги:** `web/`, `tests/e2e/` · **Зависит от:** C-201 (слит), K-301 (слит) · **Требования:** ROLE-05, ROLE-06, SEC-04, DATA-16, UI-03, UI-12

## Что сделать

1. **Подтверждение необратимых действий** — находка проверки C-201. Действие выполняется только после вопроса с именем того, кого оно касается, и с последствием:
   - «Сбросить пароль» — «Сбросить пароль «Петров П. П.»? Его открытые сессии закроются, войти можно будет только временным паролем».
   - «Заблокировать» — «Заблокировать «Петров П. П.»? Он сразу потеряет доступ».
   - «Убрать» сеть — «Убрать сеть 10.0.5.0/24? Рабочие места этой сети не смогут войти, если список не пуст».
   - «Отключить» роль — с числом её пользователей.

   «Разблокировать» и «Вернуть» роль подтверждения не требуют. Вопрос — диалог в стиле C-003, а не `window.confirm`: у него должны быть понятные кнопки «Сбросить пароль» и «Отмена», и он доступен с клавиатуры (Esc — отмена).
2. **Правило кода ККС станции** (DATA-16). Небольшая карточка в администрировании или в разделе структуры:
   - текущее правило `signal_pattern` из `GET /kks/rules` и пример разбора `example`: `01MAJ81AA203XB01` → объект `01MAJ81AA203`, сигнал `XB01`;
   - поле «Проверить код»: пользователь вводит свой код и видит разбор. Разбор делает сервер — `GET /sites/{id}/kks/resolve?code=` показывает, найден ли объект и как (`via: signal`);
   - изменение правила — `PUT /kks/rules`, только у роли с разделом `structure`. Отказ `400 kks_rule_invalid` показывается у поля.
3. **Сценарии в браузере** на настоящем сервере: отмена сброса пароля ничего не меняет; подтверждённый сброс закрывает сессию пользователя; правило `X[A-Z][0-9]{2}|-[0-9]{2}` разбирает `01TK12CKA110-03`.

## Приёмка

Ни одно действие из п. 1 не выполняется без подтверждения; отмена не отправляет запрос — это видно в сценарии по журналу (`GET /audit`).
