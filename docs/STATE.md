**Замер.** Локальный замер на сгенерированных данных, 25 полей в записи (21 текстовое). Это замер движка без сервера и сети, на машине разработки, а не приёмка PERF: приёмочный стенд — задача C-102.

**Что не дотягивает и что упрощено:**

- **Размер базы выше цели NFR-02** на этой выборке: 3,3–3,5 КиБ на запись против 3. Три четверти объёма — сам документ записи и триграммный индекс поиска. Выборка тяжёлая по тексту; на данных рабочей базы нужно перемерить после импортёра. Если цель не выполнится, варианты — пересмотреть цель или сузить набор полей в индексе поиска.
- **Сортировка — по одному полю.** Сортировка по нескольким полям в контракт не вошла.
- **Текст сортируется по кодам символов**, не по русскому алфавиту: заглавные раньше строчных.
- **`contains` по одному полю и поиск слов короче трёх символов** идут перебором реестра: 30 мс на 10 000 записей, 340 мс на 100 000.
- **Сортировка по полю-списку и по ККС** идёт без индекса.
- **Изменение флага «искать по полю» и архив поля** перестраивают индекс поиска всех записей типа в одной транзакции; на больших реестрах это нужно будет вынести в фоновую задачу (этап 4, очередь задач).
- **Копия перед миграцией не шифруется**; шифрованные копии — этап 2 (SEC-09).

## Принятые технические решения

| Решение | Почему |
| --- | --- |
| `engine` использует только стандартную библиотеку Python | Меньше зависимостей в ядре; запросы пишутся на SQL напрямую, без ORM |
| Запись — документ JSON, значения под постоянными ключами полей | Новый тип и поле без миграции; переименование не трогает данные |
| Значение справочника и ККС в записи — UUID | Переименование видно везде сразу; название приходит в `refs` ответа |
| История — разницы версий; первая версия разницу не хранит | Документ не хранится дважды: 1,1 КиБ экономии на запись |
| Внутренние номера `seq` у записей и реестров | Номер стоит в каждой строке и индексе вместо 36-символьного UUID; наружу отдаётся только UUID |
| Условия по ККС идут через таблицу связей | Точный код находится по индексу за 0,2 мс на любом объёме |
| Полнотекстовый индекс без хранения текста, триграммы | Поиск подстроки без удвоения текста в базе |
| `synchronous = FULL` | Подтверждённое изменение не теряется при сбое питания (NFR-06) |
| Пакетная загрузка — одна строка аудита на пакет | Тысяча строк журнала на тысячу записей — шум, а не аудит; история по каждой записи остаётся |
