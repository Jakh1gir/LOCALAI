- **Изменение флага «искать по полю» и архив поля** перестраивают индекс поиска всех записей типа в одной транзакции; на больших реестрах это нужно будет вынести в фоновую задачу (этап 4, очередь задач).
- **Копия перед миграцией не шифруется**; шифрованные копии — этап 2 (SEC-09).

| Проверка на схеме 34, 10 000 записей | Результат |

**Найдено при проверке на настоящей схеме:**

- Схема Local_DB опирается на собственные SQL-функции `LOCALDB_FOLD` и `LOCALDB_IDENTIFIER`. Без них проверка целостности копии падает, поэтому импортёр их регистрирует.
- SQLite создаёт файлы `-wal` и `-shm` рядом с базой даже при открытии только для чтения. Остановленная Local_DB теперь открывается как неизменяемая, и этих файлов не появляется.

**Ограничения:**

- Шифрованные пакеты `.ldbpack` не читаются — нужен каталог данных или файл базы.
- Проверено на базе, собранной генератором, а не на рабочей. Шлюз AT-19 закрывается только на копии рабочей базы.
- Поиск по строке ищет по названию значения справочника, но не по его синонимам; по синониму находит фильтр «равно».

Изменения в `engine` для переноса: заданный ID при создании типа, поля, реестра, справочника и значения; загрузка записей с готовой историей (`records.load`, `records.extend`); проверенный снимок базы (`engine/snapshot.py`); миграция `0002_import_runs`.

### K-105 · Исправления по проверке Codex (R-001) — Claude

Codex нашёл в ядре, сервере и импортёре 23 воспроизводимые находки, пять из них — с порчей или потерей данных. 21 исправлена, 2 приняты как задокументированные ограничения. Ответ по каждому номеру — в [requests/001-claude-review.md](requests/001-claude-review.md).

- Ключ `Idempotency-Key` обязателен для изменяющих запросов (API-06); слишком большое тело — `413` в общем формате.
- Копия базы делается перед каждой миграцией (DATA-11); миграция `0003` разрешает один объект ККС в нескольких полях записи.
- Глубокая страница по курсору стоит как первая и при обратной сортировке.

### K-201 · Пользователи, роли, права, сессии — Claude

Вход по личным учётным записям и права на каждом маршруте API. Контракт — [api-v1.md, «Вход и права»](contract/api-v1.md#вход-и-права), хранение — [database.md, «Доступ»](contract/database.md#доступ).

- **Роли — данные** (ROLE-01, ROLE-02, ROLE-10). Роли создаются, копируются, переименовываются и отключаются. Права привязаны к UUID роли. Стартовые роли «Администратор», «Инженер», «Наблюдатель» создаёт миграция `0004`.
- **Матрица прав** (ROLE-03). Разделы, действия над реестрами (над всеми или выбранными), ограничения полей «не видеть» и «не править», типы документов. Скрытое поле не приходит в записях, истории и версиях, по нему нельзя фильтровать, и поиск его не видит. Закрытое поле нельзя изменить даже откатом.
- **Учётные записи** (ROLE-04…ROLE-07). Администратор создаёт пользователя с временным паролем, меняет роль, блокирует и сбрасывает пароль. Временный пароль показывается один раз и в базе открытым не лежит. До смены временного пароля доступен только `/auth/*`. Журнал пишет UUID учётной записи.
- **Последний администратор** (ROLE-08, AT-22). Блокировка, смена роли, отключение роли и снятие права, после которых не останется активного администратора, отклоняются одним правилом.
- **Права на открытые сессии** (ROLE-09, AT-20). Права читаются из базы на каждый запрос; изменение действует со следующего запроса.
- **Защита** (SEC-01…SEC-03, SEC-08, API-02). Пароль хранится хэшем scrypt, токен сессии — хэшем SHA-256. Сессия живёт до 12 часов и закрывается после 15 минут простоя. После 5 неверных паролей вход закрыт на 15 минут, с одного адреса — не больше 20 неудачных входов за 15 минут. Cookie — `HttpOnly`, `SameSite=Strict`. Стартовых паролей нет: первого администратора создаёт `python -m server.admin`. Входы, отказы, действия с пользователями и ролями пишутся в журнал. Без сессии каждый закрытый маршрут отвечает `401` раньше, чем разбирает тело запроса.

### K-103 · Пакетная правка, удаление из архива, значения поля — Claude

### K-202 · Резервные копии, HTTPS, разрешённые адреса — Claude

Серверная часть этапа 2 закончена: копии (F-022, F-023, SEC-09) и сетевой режим (SEC-04). Контракт — [api-v1.md, «Резервные копии»](contract/api-v1.md#резервные-копии) и раздел «Журнал и состояние».

- **Копия** — зашифрованный файл: AES-256-GCM по кадрам в 1 МиБ, ключ из пароля через Argon2id, открытый заголовок проверяется вместе с данными. Копия делается из согласованного снимка и проверяется до шифрования; работа других пользователей не останавливается.
- **Восстановление** сначала проверяет копию: пароль, целостность, версию схемы. Затем текущее состояние упаковывается тем же паролем в защитную копию, база заменяется, схема доводится до текущей, сессии закрываются. Ошибочное восстановление отменяется восстановлением из защитной копии.
- **HTTPS.** `python -m server.admin create-certificate` создаёт ключ и самоподписанный сертификат и печатает отпечаток. В сети сервер без сертификата не запускается. Cookie по HTTPS получает `Secure`.
- **Разрешённые адреса.** Пустой список пропускает всех; адрес сервера пропускается всегда. Изменение, которое отрезало бы администратора от его же компьютера, отклоняется.

**Чем проверено.** `python -m pytest` — 200 passed, из них 14 — `tests/server/test_backups.py`: шифрование, восстановление и откат через защитную копию, неверный пароль, четыре вида повреждения файла, выход за папку копий, копия от более новой программы, адреса, сертификат, отказ запуска в сети без HTTPS. Под Uvicorn по HTTPS: вход, cookie с `Secure`, отказ без доверия к сертификату. База 15,5 МБ (10 000 записей): копия 1,1 МБ за 0,7 с, восстановление 0,85 с.

**Ограничения.** Загрузки копии через API нет: тело запроса ограничено 10 МиБ, поэтому копию с другой машины кладут в папку копий сервера. Копии по расписанию — вместе с панелью управления установщика.

## Принятые технические решения

| Решение | Почему |
| --- | --- |
| `engine` использует только стандартную библиотеку Python | Меньше зависимостей в ядре; запросы пишутся на SQL напрямую, без ORM |
| Запись — документ JSON, значения под постоянными ключами полей | Новый тип и поле без миграции; переименование не трогает данные |
| Значение справочника и ККС в записи — UUID | Переименование видно везде сразу; название приходит в `refs` ответа |
| История — разницы версий; первая версия разницу не хранит | Документ не хранится дважды: 1,1 КиБ экономии на запись |
| Внутренние номера `seq` у записей и реестров | Номер стоит в каждой строке и индексе вместо 36-символьного UUID; наружу отдаётся только UUID |
| Условия по ККС идут через таблицу связей | Точный код находится по индексу за 0,2 мс на любом объёме |
| Полнотекстовый индекс без хранения текста, триграммы | Поиск подстроки без удвоения текста в базе |
| `synchronous = FULL` | Подтверждённое изменение не теряется при сбое питания (NFR-06) |
| Перенос — одна транзакция; пробный прогон — тот же путь с откатом | Отчёт пробного прогона совпадает с тем, что сделает перенос, включая сверку |
| Пакетная загрузка — одна строка аудита на пакет | Тысяча строк журнала на тысячу записей — шум, а не аудит; история по каждой записи остаётся |
