# Реестр функций

LOCALAI 1.0 покрывает все функции Local_DB, Core и Visual (ТЗ, раздел 12). Этот реестр — список того, что должно быть перенесено. Он составлен по маршрутам трёх репозиториев и **ждёт согласования владельца**: если функции здесь нет, она не будет перенесена.

Правила:

1. Функция считается перенесённой, когда её сценарий проходит на данных, импортированных из рабочей базы Local_DB. Отметку «принято» ставит владелец.
2. Не переносится то, что функцией не является: лишние поколения чата, файлы-заплатки интерфейса, дубли маршрутов, одноразовые workflow, тесты по тексту исходников. Такие строки собраны в конце.
3. Состояние меняет исполнитель задачи в том же pull request, что и код.

Состояния: **нет** — не начато · **ядро** — логика готова и проверена в `engine`, без сервера и интерфейса · **сервер** — доступно через API · **готово** — работает в интерфейсе, сценарий пройден исполнителем · **принято** — подтверждено владельцем.

Источник — модуль старого кода, из которого берётся поведение. `LDB` — Local_DB (`apps/server/…`), `Core` — Core (`src/localdb_ai/…`), `Vis` — Visual (`src/localdb_visual/…`).

## Не переносится

| Что | Где было | Почему |
| --- | --- | --- |
| Три поколения чата | Core: `/legacy`, `/api/chat`, `experimental/agent-v2` | Остаётся один чат с возможностями всех трёх |
| Мост агента как отдельный API | LDB `agent_bridge.py` | ИИ ходит в общий API версии 1 с правами пользователя |
| Настройка подключения Core к Local_DB | LDB `core_connection.py`; Core `handshake.py` | Один продукт, подключать нечего |
| Общие пароли ролей | LDB `admin.py` (`passwords`) | Заменяются личными учётными записями — допущение Д1 ТЗ, ждёт решения владельца |
| Слои файлов интерфейса и файлы-заплатки | LDB `apps/desktop/web` (121 файл) | Интерфейс пишется заново |
| Служебные маршруты раздачи скриптов чата | Core `/api/ui/*` | Чат — часть единого интерфейса |
| Одноразовые workflow и тесты по тексту исходников | все три репозитория | Не функции продукта |
