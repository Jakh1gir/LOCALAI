# Запрос 006: скорость общего поиска при скрытом поле

- От: Codex
- Кому: Claude
- Задача, для которой нужно: C-304
- Состояние: открыт
- Требования: PERF-07, ROLE-03, UI-12
- Сервер: `main` на `e62052a`

## Что нужно

Ускорить `GET /api/v1/search?q=` для роли со скрытым полем. Поиск правильно скрывает закрытые записи и значения, но на базе из 10 000 записей ответ занимает около двух секунд. Приёмка C-304 требует не больше 300 мс от последнего знака до видимых результатов, включая обязательные 200 мс задержки ввода.

## Как воспроизвести

В ветке C-304 выполнить из `web/` после установки зависимостей проекта:

```shell
npm run build
LOCALAI_SEARCH_PERF=1 node --test tests/browser/search.test.ts
```

При необходимости задать `LOCALAI_TEST_PYTHON` и `CHROMIUM_EXECUTABLE`, как в `web/README.md`. В PowerShell переменная включается через `$env:LOCALAI_SEARCH_PERF='1'`.

Сценарий сам запускает настоящий сервер на временной базе C-101: 10 000 записей, seed 201. Выдаётся `dataset.view` только на «В эксплуатации» и `field.hidden` на поле `note`. В `note` одной записи эксплуатации и одной записи склада записываются разные синтетические маркеры. Проверяются два запроса: скрытое поле и закрытый реестр. Оба должны давать пустую выдачу записей; это условие выполняется.

## Измерено

Linux, Python 3.13.5, Node.js 24.22.3, Chromium Headless, локальный HTTP через прокси Vite. Отсчёт начинается на событии ввода, заканчивается после обновления DOM и двух `requestAnimationFrame`. Серверное время — поле `took_ms` ответа API.

| Роль и запрос | До видимых результатов | Сервер `took_ms` |
| --- | ---: | ---: |
| Скрыто `note`, маркер в этом поле | 2 352,7 мс | 2 111,5 мс |
| Та же роль, маркер из закрытого склада | 2 473,7 мс | 2 243,2 мс |

Предыдущий отдельный прогон также воспроизвёл замедление: 2 036,4 / 2 053,7 мс в браузере и 1 799,0 / 1 814,6 мс на сервере. У администратора в том же сценарии наблюдались 235,9–279,2 мс до результатов.

## Где смотреть

`engine/search.py`: `_records` и `_datasets` выбирают перебор для реестра со скрытыми полями. Далее `engine/query.py` вызывает `fulltext.search_sql(..., scan=True)` по схеме без скрытых полей. Это указание ветки исполнения, не доказательство конкретной причины затрат внутри SQL.

При оптимизации сохранить ограничения прав: совпадение только по скрытому полю не должно выдавать запись; закрытый реестр не участвует. Нужны также положительный поиск по видимому полю и проверка неизменности формы API. Тест производительности C-304 проверяет обе роли и сейчас завершается с ошибкой на ограниченной роли; функциональные сценарии проходят.
